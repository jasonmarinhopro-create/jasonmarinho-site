Il réécrit des motifs précis (« guides pour N villes », « N pages ville », « N villes ont la leur », « N villes françaises / de France », « guides de N villes ») dans une liste de fichiers (`CITY_FILES` : pages devenir, Pour qui, llms.txt, 2 articles et leurs sources, aide « statistiques de ta fiche ») et écrit `VILLES_TOTAL` dans `jason-app/lib/constants/auto-counts.ts`, lu par les messages privés (`messages.ts`), les séquences de prospection (`playbook.ts`, les séquences déjà installées en base gardent leur texte), le planning ménage et l'onglet Groupes. Test `lib/constants/auto-counts.test.ts` (valeur égale à `CITIES`). ## Créer une ville : une ville = 4 pages (17/10/2026, dépannage ajouté le 31/10/2026)

- **Depuis le 31/10/2026** : 4e page `depannage-lcd-<slug>` (voir `projet-maintenance.md`). `creer-ville.mjs` la génère (`build-pages-pros-villes.mjs <slug> --metier=depannage`) et lance `inject-metiers-ville-links.mjs` ; `verifier-villes.mjs` l'exige.

- **Règle de Jason** : « quand on crée une nouvelle ville, on la crée pour tout le monde » : page photographe & vidéaste (`photographe-lcd-<slug>`), page ménage (`menage-lcd-<slug>`) ET guide hôte (`devenir-hote-airbnb-<slug>`), au même niveau. Fini `prosOnly` (Les Sables-d'Olonne n'avait pas de guide hôte, régularisé).
- **Méthode unique** (depuis le 09/11/2026 : d'abord une ligne dans le registre `scripts/data/registre-geo.mjs`, voir `geographie.md` ; la région vient du code INSEE, plus de `REGIONS` à tenir ; + ajouter la ville à `COMMUNES` de `scripts/lib/taxe-officielle.mjs`) : (1) faits vérifiés par recherche web : entrée dans `CITIES` de `footer.js` (slug, nom, adr, occ, ann, desc) et bloc dans `scripts/data/villes-local.mjs` (`ville({...})` : réglementation ou helpers génériques `reg120` / `taxeGen` si rien de local n'est confirmé, saisons `pics`, conseils `menage` et `photo`, sources) avec `marche: { releve, sources }` pour les chiffres du marché ; (2) `node scripts/creer-ville.mjs <slug> "<commune officielle>"`. Le script génère les pages manquantes (jamais d'écrasement : pages pros seulement si absentes, guide hôte sans `--force`), relance toutes les injections idempotentes (local, taxe, estimation, liens entre les 3 pages, chiffres Google, demande inversée), ajoute les 3 adresses au sitemap, la ville à `CITY_PAGE_SLUGS` / `cityLabel` (app), à `VILLE_LABELS` (fiches pros), à la réserve de prospection, met à jour les compteurs « N villes » et les pages Pour qui, puis vérifie. Ensuite : tests de l'app, relecture, push. Des communes voisines peuvent être ajoutées à `CITY_ALIASES` / `VILLE_ALIASES` (les deux listes).
- **Guide hôte généré** (`scripts/build-guide-hote.mjs`, mise en page des anciens guides dans `scripts/lib/guide-hote-style.mjs`) : réglementation, enregistrement, taxe (remplie par `inject-taxe-villes`), saisons, photos et ménage, fiscalité 2026 lue dans `fiscal-params.mjs`, FAQ HTML + JSON-LD, sources ; chiffres du marché du bandeau annoncés comme estimations avec leur mois. Aucun chiffre sans source. Les 60 anciens guides, écrits à la main, ne sont pas régénérés.
- **Contrôle** : `scripts/verifier-villes.mjs` (job « villes » du workflow Site statique) échoue si une ville de `CITIES` n'a pas ses 3 pages, ses 3 adresses de sitemap, son bloc vérifié, sa place dans l'app ou la réserve de prospection, ou si une page n'a pas de ville.
